## 2. התנהגות (לוגיקה)

### 2.1 מצב בזיכרון בלבד (`JokeGenerator`)
- `draftTopic` — ערך השדה.
- `displayedJoke` — `{ text, topic } | null`: הבדיחה המוצגת **והנושא שבו נוצרה**. השדה `topic` הוא ה־`lastSuccessfulTopic` (ARCHITECTURE 2.2) — שמירתם יחד מבטיחה שהכותרת ו"בדיחה נוספת" תמיד תואמים לבדיחה שעל המסך.
- `requestStatus` (`idle | loading | error`), `errorKind` (`refused | general`).
- `copyState` (`idle | copied | failed`).
- `inFlight` — `useRef<boolean>` שמסומן **באופן מיידי** עם תחילת בקשה (לפני שהמסך מתעדכן), כדי ששתי לחיצות מהירות לא ייצרו שתי בקשות.
- אין Local Storage, אין היסטוריה; רענון מוחק הכול.

### 2.2 פונקציה משותפת `runRequest(topic, previousJoke?)`
1. אם `inFlight.current` → יציאה מיידית (בלי בקשה).
2. `inFlight.current = true`, `status = loading`, ניקוי שגיאה קודמת.
3. `requestJoke(topic, previousJoke)`.
4. הצלחה → `displayedJoke = { text: joke, topic }`, `copyState = idle`, `status = idle`.
   כישלון → `status = error` עם הודעת הסירוב או ההודעה הכללית; **`displayedJoke` לא משתנה**.
5. `inFlight.current = false` (ב־`finally`).

מכיוון שבכל רגע יש לכל היותר בקשה אחת פעילה, תוצאה ישנה לא יכולה לדרוס תוצאה חדשה.

### 2.3 "צור בדיחה" (Flow 1, 2, 4)
- `runRequest(draftTopic.trim())`. אחרי הצלחה, הנושא החדש הופך לנושא של "בדיחה נוספת".

### 2.4 "בדיחה נוספת" (Flow 3, ADR-3)
- מוצג רק כשיש `displayedJoke`; מתחת לכרטיס.
- `runRequest(displayedJoke.topic, displayedJoke.text)` — כלומר `topic = lastSuccessfulTopic`, `previousJoke = displayedJoke` (ARCHITECTURE 2.5). **לא** קורא את `draftTopic`, כך שעריכת השדה לא משפיעה עליו.
- מושבת בזמן טעינה (כמו "צור בדיחה").

### 2.5 "העתק בדיחה" (Flow 5, FR-04)
- `navigator.clipboard.writeText(displayedJoke.text)` בתוך `try/catch`; גם אם `navigator.clipboard` לא קיים (למשל HTTP שאינו `localhost`) — נחשב כישלון, בלי קריסה.
- הצלחה → הכיתוב על הכפתור מתחלף ל"✓ הועתק!" לשתי שניות (`setTimeout`, מנוקה בהחלפת בדיחה וב־unmount).
- כישלון → מתחת לכפתור, בתוך הכרטיס, הודעה "לא הצלחנו להעתיק. אפשר לסמן את הטקסט ולהעתיק ידנית." (בתוך אזור `aria-live`). טקסט הבדיחה נשאר ניתן לסימון.
- ההודעה/החיווי מתאפסים כשמוצגת בדיחה חדשה.
- אין שיתוף מובנה.

### 2.6 כותרת הכרטיס (`app/jokeTitle.ts`)
- `jokeCardTopic(topic: string): string | null` — `null` כשהנושא ריק; אחרת הנושא, ואם יש בו יותר מ־40 תווים (ספירה לפי `Array.from`, כמו `countChars`) — 40 התווים הראשונים + "…".
- ברכיב: `null` → "בדיחה כללית"; אחרת "בדיחה על <bdi>{נושא}</bdi>" — כך "בדיחה על cats" נקרא נכון.

### 2.7 הודעות (`app/messages.ts`)
כל הנוסחים שמוצגים במסך עוברים לקובץ אחד, מילה במילה מטבלת DESIGN: כותרת, תת־כותרת, תווית, Placeholder, "צור בדיחה", "מייצר בדיחה...", "בדיחה על" / "בדיחה כללית", "בדיחה נוספת", "העתק בדיחה", "הועתק!", העתקה נכשלה, שגיאה כללית, סירוב.
הודעות 429 / Timeout / אין חיבור / 400 **לא** נוספות עכשיו — ההבחנה בין סוגי השגיאות שייכת ל־Milestone 4 (כמו שנקבע ב־M2). עד אז כל כישלון שאינו סירוב מציג את ההודעה הכללית, שהיא נוסח תקין מהטבלה.

## 3. עיצוב (לפי DESIGN + התמונות)

**סדר הרכיבים — לפי ה־Wireframe** (ולא לפי ה־Mockup, שבו "בדיחה נוספת" מעל הכרטיס): Header → תווית + שדה + מונה → "צור בדיחה" → אזור הודעות → כרטיס בדיחה (כותרת, גוף, "העתק בדיחה") → "בדיחה נוספת". אין מסך "אודות", תפריט או ניווט.

### 3.1 גופנים
- `Fredoka` (משקל 700) — הכותרת הראשית וכותרת הכרטיס. `Rubik` (400/500/700) — כל השאר.
- טעינה ב־`layout.tsx` דרך `next/font/google` עם `subsets: ["hebrew", "latin"]`, `display: "swap"`, והצמדה כמשתני CSS (`--font-display`, `--font-ui`) על `<html>`.

### 3.2 צבעים וסגנון
- משתני CSS ב־`globals.css` לכל צבעי ה־Style Guide (`#FFD400`, `#A7D800`, `#18BFF2`, `#FF5BCB`, `#4A73E8`, `#FF9A1F`, `#FF4B39`, `#111111`, `#FFFFFF`).
- **רקע:** אזור עליון צבעוני בסגנון Pop Art (פסים אלכסוניים בכחול/ורוד/צהוב באמצעות `linear-gradient`, ונקודות Halftone עדינות ב־`radial-gradient`), ומשטח התוכן בהיר — כמו ב־Mockup. התוכן תמיד בטקסט כהה על רקע בהיר.
- **כותרת ראשית:** Fredoka Bold, ‏44px (40–48), מתאר שחור (`-webkit-text-stroke` / `text-shadow`) וצל קומיקס קצר; ממורכזת. תת־כותרת Rubik 18px.
- **שדה:** לבן, פינות מעוגלות, מסגרת כהה 2px, יישור לימין, `dir="auto"` (נשאר); מונה `n/100` קטן (13px) עם `dir="ltr"` (נשאר).
- **"צור בדיחה":** צהוב `#FFD400`, טקסט שחור Bold ‏19px, מסגרת שחורה 3px, פינות מעוגלות מאוד, צל קצר מלא (`box-shadow: 0 4px 0 #111`), רוחב מלא, אייקון שרביט. מצב לחוץ — הצל מתקצר; מצב מושבת — שקיפות.
- **"בדיחה נוספת":** כחול `#4A73E8` עם טקסט לבן (ניגודיות תקינה), מסגרת ופינות מעוגלות, אייקון רענון, רוחב מלא, מתחת לכרטיס.
- **"העתק בדיחה":** כפתור שלישוני קטן יותר, לבן עם מסגרת כהה ואייקון Clipboard, בתוך הכרטיס.
- **כרטיס בדיחה:** לבן, פינות מעוגלות, מסגרת שחורה 3px ו־Chunky Shadow בצבע (למשל `6px 6px 0` כחול שמיים); כותרת Fredoka ‏28px; גוף Rubik ‏18px, `white-space: pre-line` (שבירות שורה נשמרות), `overflow-wrap: anywhere`, `dir="auto"` (בדיחה באנגלית מוצגת LTR, טקסטי הממשק נשארים RTL). פרצוף צוחק קטן כעיטור בפינה, שאינו מסתיר טקסט.
- **טעינה:** שלוש נקודות (כחול, צהוב, ורוד) בהקפצה + "מייצר בדיחה...", כמו ב־Style Guide. תחת `prefers-reduced-motion` — ללא אנימציה.
- **שגיאה:** תיבה ורודה־אדומה בהירה עם מסגרת אדומה ואייקון "!" (טקסט כהה לקריאות). תיבת 429 הכתומה — ב־M4.
- **עיטורים:** SVG פשוטים בקוד בלבד (`Decorations.tsx`), עם `aria-hidden="true"` ו־`pointer-events: none`; לא מורידים איורים מבחוץ, ולא הופכים ללחצנים.
- **מובייל:** עמודה אחת, `max-width: 480px`, שוליים 20px; תוכן ארוך גולל את העמוד; `overflow-x: hidden` נשמר ואין אלמנט רחב מהמסך.

### 3.3 נגישות
- כל הכפתורים הם `<button>` אמיתיים עם טקסט; האייקונים `aria-hidden`.
- `:focus-visible` — מתאר ברור (למשל 3px כחול) על שדה וכפתורים.
- אזור ההודעות ואזור התוצאה נשארים `aria-live="polite"`; הודעת שגיאה עם `role="alert"`; הודעת כישלון העתקה ו"הועתק!" באזור `aria-live`.
- הכרטיס הוא `<section>` עם `aria-labelledby` לכותרת שלו.

## 5. בדיקה עצמית בזמן הבנייה

1. `npm run typecheck`, `npm run lint`, `npm test`, `npm run build` — הכול עובר.
2. `npm run dev` ובדיקה בדפדפן הפנימי (מספר קטן של בקשות לשמירה על עלות):
   - מצב ריק: רק Header, שדה ו"צור בדיחה"; אין כרטיס ואין "בדיחה נוספת".
   - "חתולים" → כרטיס "בדיחה על חתולים". שינוי השדה ל"כלבים" — הבדיחה והכותרת לא משתנות. "בדיחה נוספת" → בקשת הרשת כוללת `topic: "חתולים"` ו־`previousJoke` = הבדיחה שהוצגה; הבדיחה החדשה שונה. "צור בדיחה" → `topic: "כלבים"`; אחריו "בדיחה נוספת" שולח "כלבים".
   - שדה ריק → "בדיחה כללית". "cats" → "בדיחה על cats", גוף הבדיחה מוצג LTR, הממשק נשאר RTL.
   - נושא ארוך מ־40 תווים → כותרת מקוצרת עם "…".
   - העתקה: לחיצה → "✓ הועתק!" לשתי שניות, ובדיקת התוכן שהועתק מול הטקסט המוצג. דימוי כישלון (`navigator.clipboard` חסום דרך כלי הבדיקה בדפדפן בלבד, לא בקוד) → הודעת הכישלון, בלי קריסה.
   - לחיצות מהירות: שתי לחיצות רצופות על "צור בדיחה", ו"צור בדיחה" + "בדיחה נוספת" ברצף → ב־Network יוצאת בקשה אחת בלבד.
   - טעינה: נקודות + "מייצר בדיחה...", שני הכפתורים מושבתים, הכרטיס הקיים נשאר. שגיאה (סירוב) → תיבת שגיאה, הכרטיס נשאר, ההודעה נעלמת בבקשה הבאה.
   - כל הטקסטים במסך מושווים לטבלת הנוסחים ב־DESIGN.
   - `resize_window` למובייל (375px): סדר הרכיבים, קריאות, ללא גלילה אופקית (`scrollWidth === clientWidth`); בדיחה ארוכה גוללת את העמוד.
   - מקלדת: מעבר ב־Tab בין שדה ← "צור בדיחה" ← "העתק בדיחה" ← "בדיחה נוספת", עם מסגרת פוקוס נראית; Enter בשדה יוצר בדיחה.
   - Screen Reader: בדיקת עץ הנגישות (`read_page`) — שמות כפתורים, `aria-live`, כותרת הכרטיס. בדיקה עם קורא מסך אמיתי (VoiceOver/TalkBack/NVDA) — ע"י המשתמש, אדריך אותו.
   - רענון מוחק את הבדיחה.
   - צילום מסך להשוואה מול ה־Mockup וה־Style Guide.
3. סגירת שרת הפיתוח בסיום; סימון 🟡 ב־`MILESTONES.md`; ללא commit.

## 7. מחוץ לטווח של Milestone 3
ניסיון חוזר ב־Backend, הודעות שגיאה מובחנות (429 / Timeout / אין חיבור / 400) ותיבת המגבלה הכתומה, `AbortController`, Headers אבטחה, WAF ו־PWA (אייקונים ו־Manifest) — כולם Milestone 4. אין שינוי ב־API או בהוראות למודל. אין Database, Local Storage, היסטוריה, מסך "אודות" או שיתוף.
